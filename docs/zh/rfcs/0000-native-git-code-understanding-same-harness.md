# 自研引擎与 CodeGraph 同协议实测报告

实测日期：2026-09-22（北京时间）。

**自研引擎已在 worktree5 的同一套六题实验中跑通，但本轮没有证明它优于 CodeGraph。** 36 次完整对照的主成绩为 OFF **10/12**、CodeGraph **11/12**、自研 **11/12**。自研与 CodeGraph 各有一道不同的失败，不能把总分相同理解为逐题等价或质量非劣效。

自研相对 CodeGraph 的同题配对耗时中位数 **增加 24.1%**，累计输入 token **增加 34.4%**，非缓存输入 **增加 5.8%**；两组都成功的 10 对，耗时仍增加 25.6%。自动准备命中目标为 **4/12 对 6/12**，自研另有 **3 次超时、1 次缓存不可用**。当前适合继续显式试用和优化接入成本，不支持据此默认替换。

## 保留的失败与修复质量

| 运行 | 失败原因 |
| --- | --- |
| topic-default-0-off | 24 次模型请求预算耗尽；产物仍通过 84 项测试 |
| lexical-callers-0-codegraph | 图工具参数错误后 UnexpectedModelBehavior；没有最终答案 |
| lexical-callers-1-off | MemoryService.search 定义起始行误报为 436，应为 412；严格匹配 5/6 |
| eligibility-callers-1-native | _RelationalTriggers._sources 误报为 _RelationalSources._sources；严格匹配 3/4 |

18 份修复补丁均保留。额外检查以 UID 1001 将普通未跟踪 Python 文件设为不可读，基线拒绝索引；三组第一轮（repeat=0）软链接补丁也正确拒绝，第二轮（repeat=1）补丁却都成功索引并把该文件标为 `symlink_or_submodule` 遗漏。三份退化均来自过宽的 `OSError` 处理。这复现了固定测试覆盖不足的问题，没有证据表明换成自研引擎消除了这类修复错误。

自研为 823/823 个 Python 文件生成提取结果，490 个文件包含共 3,936 条 `unsupported_scope` 诊断，来自 lambda、推导式和生成器表达式；没有 `parse_error` 诊断。适配层将含任意提取诊断的文件计入旧协议的 `parse_failures`，所以原始字段显示 490。这表示部分作用域被保守跳过，不是 490 个文件完全未索引；也不能声称完整静态关系覆盖。原始字段保留，解释单列。

## 比较对象与固定条件

三组均使用 worktree5 优化接入快照 `a677359cd0ae80f164d317b4573ed9a983e22f42`，tree 为 `aa98af2228ac09abb2a2a80065d16183dee4d4ca`。OFF 关闭代码注入和图工具；CodeGraph 使用原优化接入的 CodeGraph 1.6.0；自研组仅替换底层适配器，调用已交付原生引擎的提取、解析、SQLite 存储和搜索实现。

| 条件 | 固定值 |
| --- | --- |
| 任务 | 原六题：3 道预置缺陷修复、3 道直接调用者分析；每题每组重复 2 次 |
| Agent | 原 PydanticAI worker 文件逐字节相同，SHA-256 `dc5a19b1460baf83185aaaa6b3d5032c6a0a4af398dd85588906e87a7bfdd911` |
| 模型 | `qwen3.7-plus`；temperature 0；每响应输出上限 5,000 token |
| 执行预算 | 每次最多 24 次模型请求、累计 600,000 token、360 秒 Agent 超时 |
| 工具 | 原文件列举、搜索、读取、替换、固定测试工具；两组 ON 额外提供相同 `query_code` schema |
| 代码预算 | 查询 5 秒；自动准备 8,000 UTF-8 字节、图响应 16,000 字节、普通工具输出 24,000 字节 |
| 自动注入 | 同一符号线索提取、未聚焦输入跳过策略和 `PreparedContextBuilder`；关闭历史检索和生成式召回门控 |
| 调度 | 原同题轮换顺序；36 次串行执行；计时期间不并行跑性能诊断或回归 |
| 源码 | 同一冻结语料；题目字段、提示、预置缺陷和金标准仅替换本机根路径 |

OFF 和 CodeGraph 对照均重新运行。worktree5 原报告的 10/12、10/12、12/12 是历史观测，不充当本轮并发对照，也不与本轮合并。这里只复用其六题 Agent 实验；没有重做整份历史报告中的 HTTP、Hook、向量数据库或全部语言检索测量。

## 引擎替换边界

自研引擎来自已交付 wheel，SHA-256 为 `488c8fad08977c444bd4e702f53b686ad0d242b3b4b552ca1fd7f943d14427fc`；15 个原生模块与工作区源码逐字节核验。独立 Python 3.14 环境中安装该 wheel，解析依赖沿用已记录的版本和文件哈希。Agent 使用 worktree5 的同一个解释器和 PydanticAI 依赖。正式开始前封存 1,737 个输入文件，每次运行前重新检查。

适配层将原 `engine.cjs` 的定义筛选、同名关系保护、调用者扩展、遍历和数量限制翻译为 Python。13 个确定性用例对照原 JavaScript 输出及错误，覆盖歧义、路径过滤、循环、菱形路径与结果限制。原生索引负责符号和边的内容、解析判断与搜索排名，接入策略保持一致。

共同接入层仍保留源码采集、新鲜度检查、缓存校验、每次查询复制索引、片段回填和字节预算。自研索引保留 `facts/` 与 `source/`，因此也承担这些文件在原缓存流程中的扫描与复制成本。这轮测量不代表自研完整服务直接查询不可变索引或增量同步的性能。保留同名保护也可能过滤自研已正确解析的边，不能据此判断自研关系覆盖率的上限。

## 评分与用量口径

编码完整成功要求 Agent 正常结束、测试未改、修复产物通过原固定测试。Topic Memory 和 UTF-8 两题各 84 项测试，软链接题 11 项。分析题要求目标和直接调用者集合的路径、限定名、定义起始行全部正确，并保持源码与测试不变；三个金标准分别有 2、6、4 个直接调用者。三道修复题均已验证原基线通过、预置缺陷失败。

“产物测试通过”单列，不能将请求预算耗尽但补丁通过的运行改记为完整成功。软链接补丁另外复用原实验的普通文件不可读检查；该补充结果不改变主评分，也不代表补丁已经达到生产质量。补丁源码检查由本助手完成，并非独立人工审计。

任务时间沿用原 worker：包含自动准备、模型和工具执行，排除建图、进程启动、最终独立测试；建图时间单列。配对变化先计算同题同重复的比值再取中位数。Token 使用服务返回的累计计数，非缓存输入为输入减缓存读取；不是去重后的上下文长度或实际账单。缓存命中、服务负载和未隔离的主机均可能影响结果。

## 分析评分器的统一修正

实验包装器动态加载原 worker 时漏掉了 `sys.modules` 注册，导致 Pydantic 在模型返回最终文本后，无法解析分析答案中的 `Location` 前向类型引用。原 worker 内容没有变化；其输出类型是字符串，分析答案校验仅在模型运行结束后执行。原始回答已在校验之前保存在 `answer_text` 中。

正式运行期间保持封存代码不变。全部 36 次结束后，以正确注册的同一个原 worker，对全部 18 份固定分析回答统一离线评分；没有重新请求模型、编辑回答、改变标准或按成绩挑选重跑。无最终回答的真实执行失败仍为失败，18 份修复记录不变。原始记录与错误评分完整保留，主表使用单独的 `corrected-summary.json`。

修正预检确认工具 schema 完全相同，三个金标准答案通过，错误限定名、缺失答案、歧义双答案均被拒绝。`scorer-correction.json` 保存逐次前后成绩和原记录哈希；`final-audit.json` 复核全部分析记录均覆盖、模型输出和用量未变、修复记录未变。交付的包装器修复加载注册，并在预检中增加相同评分检查；执行时的封存包装器另行保留。

## 结论边界

36 次运行只有 6 道独立任务，其中修复、分析各 3 道；重复不是新增独立样本。任务取自已知回归和明确符号分析，没有盲测新仓库，也不是原生 Codex 或 MCP 宿主评测。结果可判断这套固定接入下的功能表现与失败位置，不能证明普遍优越、非劣效、账单下降或默认启用所需的发布门槛。

此前另一套历史任务协议的原生修复 0/23 结果继续保留在 [A/B/C 实测报告](0000-native-git-code-understanding-experiment.md)。两次实验的任务、工具和预算不同，不能直接将分数相减归因为引擎进步。
