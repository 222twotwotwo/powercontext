# 原生代码理解 A/B/C 实测报告

原生仓库查询和产品接口已完成真实验收，但本次任务实验不足以证明原生引擎提高修复成功率或达到发布所需的非劣效与效率门槛。能力保持实验性质、默认关闭。功能与性能数据见[实现与真实验收](0000-native-git-code-understanding-validation.md)，使用方式见[仓库代码工作流](../docs/workflows/repository-code.md)。

## 实验协议

固定 worktree5 接入协议的另一组对照见[同协议实测报告](0000-native-git-code-understanding-same-harness.md)。两组协议的任务、工具和预算不同，成绩分别保留，不直接合并。

- 日期：2026-09-21；请求模型标识 `qwen3.7-plus`，temperature `0.2`，推理配置沿用提供方默认值。
- A 使用实际 CodeGraph 库，提交 `ba3c21e50d9129d2f5f3843ec3728868ae6d47a1`，通过本机 Node 适配器调用；B 使用原生 Python 引擎；C 使用普通文件工具。生产代码不依赖 CodeGraph。
- 16 个独立任务，每任务 3 次重复、每次 A/B/C 三臂：8 个历史修复、4 个理解题、4 个影响题。另有 4 个 pilot，不纳入成绩。修复任务均先验证基线失败、参考修复通过隐藏测试。
- 三组使用相同公开历史源码、空且只读的历史上下文、普通文件工具、任务提示和 16,000 字节输出上限，按 Latin 顺序轮换。工具不提供网络、Git 历史、其他 checkout 或子 Agent。
- 每任务最多 24 轮响应、480 秒调查预算、320,000 输入 token 和 20,000 输出 token 的准入预算，每响应最多 2,000 输出 token；已发出的响应可能越过准入阈值，记录实际用量。提供方请求超时为 120 秒。
- 基础设施失败使整个三臂组合失效，最多保留 3 次尝试；普通超时、轮数/token 用尽、模型协议错误均作为有效结果。正式 runner 为 `native-code-evaluation-5`。
- 同时运行 2 组三臂组合。每次 A/B 启动 Agent 前，已知符号预检必须返回非空证据；探针计入准备成本，结果不交给模型。
- 共执行 **171 次尝试**，最终选中 **141 次有效运行**，另有 **3 次选中但无效的运行**。原始尝试全部保留。

## 评价器修正

任务提示要求文件路径和行范围，没有限定冒号格式。原评阅器未识别 Markdown 文件路径后面的 `lines 12–20`、`L12–20` 等明确引用，错误地将部分回答视为没有证据。已归档并排除先完成的 13 份评阅，使用 `native-code-evidence-review-2` 对全部 72 份固定回答重新评阅；标准、模型设置、任务记录和修复隐藏测试成绩均未改动。这是运行后公开说明的评价器修正，与原协议归档的评阅器区分记录。

引用交付回归 9 项通过。全部回答中，37 份补回此前漏掉的明确范围；未提取到行范围的回答从 26 份降为 7 份。开放式范围、缺失文件和无效行号仍标为错误。可移植数据的 `review_correction` 保存评阅器与解析器摘要、作废评阅及修正评阅的已观测用量，源码另存于 `corrected-review-source/`。评阅成本不混入 Agent 执行成本表；SDK 重试和中断请求的用量无法完整计费。独立人工复核仍未完成。

## 作废比较及保留成本

协议 4 执行了 159 次尝试，但适配器将 CodeGraph 的绝对源码路径丢弃，原生查询也超出时限；所有交付图结果均为空或错误，因此该批数据作废，不能比较引擎质量。`formal/` 和 `formal-review/` 保留会话、已观测 token 和 46 份未完成整批的自动评阅。可移植数据的 `discarded_comparison` 单独记账，不混入协议 5 的质量与成本统计。协议 5 开始前已通过适配器小仓库及真实历史源码探针。

## 证据与使用判断

协议、分任务统计和聚合结果在本机保存于 `.venv/evaluation/native_code/results/2026-09-21.json`，不纳入版本控制。本机原始证据根目录为 `/data/codex-tmp/native-code-20260921/`，包含 `formal-2/`、`formal-2-review/`、`formal-2-summary.json` 和 `formal-2-audit.json`。`formal-2/frozen-source/` 保存与协议哈希一致的引擎和 runner 源文件；会话、原始引擎响应、源码清单、候选修改和隐藏验收日志均保留。

实验构建包含运维 tracing、缓存清理和路径边界计数。交付构建还在索引事务结束时显式关闭 SQLite 连接，以消除依赖垃圾回收的资源释放；提取、关系解析、排名和证据渲染规则不变。成绩与执行成本归属于协议归档构建，交付源码摘要单列于数据文件的 delivery_build，并经资源回归与安装包验收。原始证据保留在本机，可移植聚合数据不能替代独立查验。

当前适合显式索引、查询和小范围试用。默认启用仍需更可靠的共享 Agent 工具执行、更多独立任务、独立人工复核，以及同步性能达到目标的证据。功能验收通过不等于这些发布门槛已经成立。
